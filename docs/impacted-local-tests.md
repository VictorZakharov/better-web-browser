# Responsibility-based local tests

During iteration, use `./scripts/run-impacted-tests.ps1` to inspect the affected-test plan and add `-Run` to execute it. The default compares all tracked working changes against `HEAD` and also includes untracked files, so previously committed batch work does not force unrelated iteration groups to repeat. Deletions and both sides of renames are included. Use `-Base <commit>` for a different development checkpoint or `-Base origin/main` to inspect the entire branch; the final PR gate remains unconditional against the complete PR head.

The ownership catalog in `scripts/impacted-tests-plan.ps1` follows existing responsibility modules. Canvas painting/state/text/image ownership includes its Canvas library and contained-renderer contracts, then follows the downstream edge to WebGL source-upload contracts: rows, regions, DOM bindings, video/security admission, owned/queued uploads, float-image compatibility and the basic public texture API. An image-row change does not select unrelated shader, query, uniform or transform-feedback suites; a native WebGL backend change still selects the whole WebGL family. Shared script coordinators select the full script library and renderer/live-runtime integrations. Broader groups supersede narrower groups, so shared changes do not run the same subset again. Unknown files, dependency/build changes and inconclusive discovery conservatively select all Rust targets and doc tests. This is an initial explicit map for rendering/script work, not a guessed complete repository dependency graph.

New modules should have one clear owner, isolated unit tests, and downstream contract tests where their output crosses an API, ownership or process boundary. When adding a responsibility, extend the catalog and its self-tests together; do not add a narrow rule just to make a particular diff fast. A source-file name alone is not evidence that its consumers cannot break. Shared state, serialization, bootstrap assembly and callback/lifecycle coordinators remain broad until their contracts are separated. Non-Markdown unknown files are never silently skipped. Cargo filters that match zero tests fail rather than reporting a false green.

Examples: `./scripts/run-impacted-tests.ps1 -ChangedPath src/engine/script/canvas_host/glyph_paint/shadow.rs` explains the Canvas-to-WebGL closure; changing `src/engine/script/engine/bridge.rs` instead selects the shared script/integration groups. `./scripts/test-impacted-tests.ps1` checks the selector without launching browsers or compiling the project.

Run `./scripts/run-impacted-tests.ps1 -Final -Run` once the implementation is ready for a PR. It always runs all Rust targets and doc tests, even for a Markdown-only diff. This is the test part of the final gate, not a replacement for full-target Clippy, formatting, source-size checks, relevant visual/WPT/Khronos or other harness checks, the final release build, and CI. If a gate fails, repair it with focused tests before repeating the final gate.

Prepare the normal developer environment first (V8/native toolchain and G: Cargo/temporary storage). On this Windows workstation the runner refuses a C: target, defaults to four build jobs and one test worker, keeps temporary files under its G: target, and restores its process environment afterwards. Renderer/live-runtime groups must run as the normal Windows user, preserving their production hidden launchers. The selector is local-only; CI remains the unchanged smoke gate. Elapsed test time still includes compilation and shared-machine scheduling.
