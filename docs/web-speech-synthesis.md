# Web Speech synthesis on Windows

Breeze implements a bounded subset of the [Web Speech API synthesis interfaces](https://webaudio.github.io/web-speech-api/#speechsynthesis-interface): `speechSynthesis`, `SpeechSynthesisUtterance`, `SpeechSynthesisVoice`, and synthesis start/end/error/pause/resume and voice-list events. Speech recognition is not implemented. Word/mark boundary events and elapsed-time/character offsets are not yet provided; applications should not depend on those callbacks. Voice discovery starts only when a page calls `getVoices()`, so an otherwise idle page emits no speech IPC or native speech initialization.

The renderer owns JavaScript objects and event dispatch, but never opens an audio device. Its document-scoped, bounded requests cross the renderer protocol to a browser-owned worker. On Windows that worker uses Microsoft's [SAPI `ISpVoice`](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/ee125164(v=vs.85)) to enumerate installed desktop voices, select one, set approximate rate and volume, apply a pitch adjustment to escaped SAPI markup, and speak asynchronously to the default output device. Each active document has an independent native voice and pause/queue state; pausing one tab does not pause another. The installed-voice list is sampled on first request and cached for this browser process, so voice installation changes during a running session require a restart. Rate and pitch mapping are approximations because SAPI's scales differ from Web Speech's. Voice availability and pronunciation depend on the host's installed SAPI voices.

For unsolicited-audio protection, Breeze requires a current, active document with a trusted transient user activation for each `speak()` submission. The activation is document-scoped and expires after five seconds. Multiple `speak()` calls in the same activation may enter the bounded native queue; a later independent call needs a new activation. This is a Breeze admission policy, not a requirement of the Web Speech specification. `getVoices()`, `pause()`, `resume()`, and `cancel()` do not require activation. Navigation, renderer replacement, and tab close retire the old `(tab, renderer session, document)` owner and cancel its audio, even if the worker command mailbox is full. A renderer retry may reuse a document number without inheriting the retired session's authorization.

Retirement keeps one high-water mark per tab for the lifetime of the browser process, including closed tabs. This prevents late queued messages from reactivating a retired voice; it does not grow with repeated navigations in one tab.

The renderer protocol rejects utterances over 16 KiB, invalid numeric settings, excessive voice metadata, and malformed updates. The browser worker bounds its incoming command mailbox, active document voices (16), and pending utterance queue (32 per active document). Cross-document or stale-session updates are discarded. Page text is XML-escaped before SAPI pitch markup is generated, so text cannot inject native synthesis instructions.

Speech updates use a nonblocking renderer mailbox: a renderer that stops draining it cannot strand the browser's cancellation worker. Under sustained mailbox saturation an event, including a terminal event, may be dropped, leaving that document's JavaScript queue state stale until navigation. The native voice still stops on retirement. Reliable nonblocking event replay remains follow-up work.

Tests cover JS command/event behavior, protocol validation, owner retirement, and installed voice metadata. The native waveform test redirects SAPI to a temporary WAV file and verifies nonempty output; automated tests never play audio or open a visible browser window. A machine without desktop SAPI components skips the host-dependent waveform test while retaining the pure validation tests.
