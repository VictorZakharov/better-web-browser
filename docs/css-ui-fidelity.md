# CSS UI fidelity: October 10

This batch fixes general CSS/layout/text/paint contracts exposed by Last Stand's UI. The application is not patched, downgraded, or given browser-specific styles. The locally retained comparison uses the complete 30-file production asset set, including all 21 WebP icons; the earlier eight-file capture's missing icons were an incomplete-fixture problem, not evidence that the browser could not decode them.

## Implemented contracts

- `zoom` retains authored/computed values and is non-inherited; used geometry includes the product of ancestor zooms. CSSOM client/offset/scroll measurements remain in the appropriate unscaled coordinate space, while bounding rectangles and device-pixel ResizeObserver sizes include used zoom. Zero computes as zero but has a used factor of one. Extreme used products are bounded to prevent zero divisors/infinite device geometry; authored values are not rewritten.
- Column flex layout resolves finite main sizes, automatic margins, min/max freezes, reverse order, and per-item cross alignment. Scroll containers can shrink with a zero automatic minimum. Intrinsic text contributions use the same case transformation as final layout, without changing DOM strings or source mappings.
- Grid placement distinguishes spans from numbered lines, supports bounded row/column implicit flow and dense placement, overlapping area placements, implicit track patterns, and definite fractional rows. Dots in template strings are null-cell tokens, not part of adjacent named areas. Hidden grid pages retain their shared track without making a fixed-height parent grow to their unconstrained contents.
- Ordered background image layers independently cycle their size, position, and repeat lists. Supported linear/radial/repeating gradients use the existing tiny-skia raster backend, current color, stop fixup, and premultiplied interpolation. The default positioning area is the padding box; the default background clip includes the border box.
- Radial gradients resolve explicit circle lengths, ellipse length/percentage pairs, and closest/farthest side/corner extents against the image box. Degenerate ellipses use the specified limiting shape or final/averaged color rather than dividing by zero. The individual `translate` property composes before the transform list, retains deferred percentages, establishes containing blocks even at zero, and supports keyframe interpolation; it moves painting and visual geometry without changing normal-flow allocation.
- Outer/inset box shadows use bounded masks and the existing Gaussian blur implementation. Rounded backgrounds and translucent borders retain alpha until compositing over the real scene, rather than guessing a white backdrop. Generated images are renderer-local, bounded, translation-independent, reused across equivalent frames, and published through existing owned image deltas. Raster dimensions account for fractional device scale.
- Normal line height uses the selected font's ascent/descent/leading and fallback-font coverage; explicit numeric/length line heights remain authored constraints. Unicode emoji presentation uses the already-locked ICU property data rather than a broad symbol-block heuristic. Common-script monochrome symbols can fall back to the platform symbol face after authored families.
- `scrollbar-width:thin/none` affects actual gutters and painting; `none` does not disable scrolling. Inherited `scrollbar-color` is painted without flattening away transparency.
- Alpha image masks now apply to assembled element groups, including children and borders. Gradient and URL layers share image sizing/position/repeat parsing, use the initial border-box geometry, and combine with source-over alpha. A failed resource or a transparent layer stays transparent; masking establishes a stacking context but does not alter layout or hit testing. Native mask/opacity nesting retains the actual scene backdrop and the original mask coordinates during partial repaint.
- Ordinary mouse movement has one renderer interaction in flight, with the latest unsent absolute position retained in the browser. Coalescing stops at clicks, button/modifier/target changes, leave events, and relative-motion transitions. Exact document/sequence completion releases backpressure independently of whether the cursor image is already stale. Scrollbar drags and rejected duplicate sequences also complete; navigation and renderer exit retire the flight. Pointer-locked relative deltas remain additive, not replaceable positions.

These are implemented slices, not complete CSS conformance. Named grid-line placement, implicit tracks before the explicit grid, vertical writing-mode layout, gradient interpolation hints/color spaces, conic gradients and text shadows are not established by these changes. Scale/rotation and nonzero Z translation remain unsupported, including the loading screen's progress-bar scale and reversed smoke layer; unsupported transform grammar is not advertised as implemented. Mask luminance modes, alternate origin/clip boxes, non-additive composites, SVG `<mask>` references, and masked native child controls remain unsupported. Existing row-flex and native-control limitations remain outside this column/paint slice.

The added direct dependencies reuse already-locked packages: `icu_properties = 2.0.2` through URL parsing (Unicode-3.0) and `smallvec = 1.15.2` for owned inline GPU operands (MIT/Apache-2.0). Their licenses are covered by the dependency policy and third-party notices. No upstream source, game assets, captured screenshots or profiles are imported into the repository.

## Replays and evidence

The pause-menu slice corrects the general [grid item automatic minimum](https://www.w3.org/TR/css-grid-1/#min-size-auto): explicit `min-width:0` and scrollable overflow permit fractional tracks to shrink below descendant min-content widths, while explicit min-content tracks and definite minima retain their constraints. Cyclic percentage minima use their intrinsic zero minimum instead of the entire grid's width. The separate [checkable grid fixture](../benchmarks/ui/fixtures/checkable-grid.html) covers overflowing descendants, nested flex actions and controls without importing game styling.

Checkbox and radio ink uses the existing tiny-skia raster backend, with DOM-owned geometry, live checked/indeterminate/disabled state, inherited accent color, and `appearance:none` suppression. Cached ink keys include state and DPI, while the semantic tree retains checkable roles, labels and checked state after raster replacement. Native text-edit windows must never cover these widgets. The appearance/accent implementation is a checkable subset: `CSS.supports` does not advertise a complete native-control appearance contract for selects, sliders or progress bars. Primary contracts are [HTML rendering](https://html.spec.whatwg.org/multipage/rendering.html#the-input-element-as-a-checkbox-and-radio-button-widgets), [CSS UI appearance](https://www.w3.org/TR/css-ui-4/#appearance-switching), and [HTML accessibility mappings](https://www.w3.org/TR/html-aam-1.0/#el-input-checkbox).

The application reference is Chrome 154.0.8037.98 at a 1262 by 539 CSS-pixel content viewport, device scale 1, a fresh profile, cache-disabled Chrome navigation, and 60 seconds of settling. Breeze uses its guarded hidden benchmark mode and the opt-in graphics renderer budget. Captures are functionality/visual checks, not startup timing or sustained gameplay measurements. Random equipment and animated scene state are not controlled, so whole-page pixel error is not used as a claim of parity.

Original screenshots, reports and the preceding release executable are retained in `G:\Git\better-web-browser\target\game-ui-fidelity-20261010`. `ui-chrome-before.png` is the reference and `ui-breeze-before.png` is the untouched main baseline. Iteration captures use explicit candidate names; the final-source capture is recorded in the pull request. Screenshots are kept out of commits as required by the artifact policy.

The isolated font fixture matches Chrome's observed line heights: 20px Arial with fallback symbols, 27px; Times New Roman, 23px; Segoe UI, 27px; explicit 30px line height, 30px; and a 13px zoomed/padded label, 18.90625px. These measurements describe the fonts installed on this Windows machine, not portable constants for every platform.

The checked-in [small UI fixture](../benchmarks/ui/fixtures/css-ui-fidelity.html) separates panel sizing, overlapping grid pages, adjacent null cells, scrolling inventory, transformed labels, monochrome symbols, gradient layers, inset shadows, and rounded borders from the game. Serve it with `scripts/serve-alpha-fixtures.ps1`; capture Breeze only through `scripts/run-hidden-benchmark.ps1`, and use the existing Chromium harness with unified `--headless`/`CreateNoWindow`. Use one browser worker and keep profiles/output on G:. This fixture is local verification, not an expansion of CI beyond its smoke gate.

The [tooltip command fixture](../benchmarks/ui/fixtures/tooltip-layout.html) checks actual content, nonzero size, and fresh positioned rectangles after each content/size/position sample. Three sequential fresh-profile runs used Chrome→Breeze, Breeze→Chrome, then Chrome→Breeze, with no agent-owned build or suite overlapping. Each has one cold and four subsequent samples. Chrome cold totals were 5.1/6.1/5.7 ms and subsequent totals 0.4–0.7 ms; Breeze cold totals were 83.7/81.8/81.9 ms and subsequent totals 23.9–31.3 ms. Those elapsed command measurements include shared-machine scheduling and do not establish isolated CPU cost or Chrome parity. Full-page geometry remains a measurable optimization target.

The [pointer transport fixture](../benchmarks/ui/fixtures/pointer-backpressure.html) performs real tooltip content and geometry work on mousemove, without sleeps or busy loops. A guarded hidden run submits 122 positions (20→620→20 at y=100), with no delay between actions and five seconds of final settling. Before backpressure, only 45 moves had executed at capture; the tooltip remained at x=240 and continued along the obsolete forward path. The exact terminal position, actual tooltip rectangle, event count, and individual replay reports are retained for before/after verification rather than treating dropped intermediate absolute positions as lost relative movement.

Three sequential pairs alternated before→after, before→after, then after→before without overlapping this agent's builds/suites. Before captures had processed 45/44/40 moves and were still at x=240/235/215 after five seconds. After captures processed the first and final absolute positions, with the painted tooltip at x=20 in every run; elapsed time from the first handled event to completion was 204/145/158 ms. The screenshot and live rectangle independently verify the final position. This is a backlog regression check, not a claim that individual tooltip layout commands now match Chrome or that end-to-end game timing is isolated CPU cost.

Eight live-runtime fixtures previously painted only a short green body over an explicitly red root while asserting a green viewport center. Chrome and unchanged main reproduce that red center. Their bodies now explicitly fill the viewport; the asynchronous execution/order and pixel assertions remain intact. A separate unit test retains the short-body/root-background contract from CSS Backgrounds 3, so this fixture correction cannot silently become a body-background propagation workaround.
