# Loading animation primitives

This slice repairs the browser primitives used by an SVG title that becomes a WebGL particle field and gathers into a smaller lobby title. It changes no application source, assets, quality settings, watchdog thresholds, or remembered preferences. A gradual progress bar is the same general CSS transform problem, not a special loading-bar implementation.

## Geometry and painting

The retained display list now carries finite 2D affine boundaries for translation, scale, rotation, skew and matrix transforms. Nested matrices compose before deriving visual bounds, and hit tests invert the local rectangle rather than accepting the empty corners of a rotated bounding box. Logical client/offset/ResizeObserver sizes remain untransformed. Scroll displacements follow the container's transformed axes, not the child's axes. See the [CSS Transforms rendering model](https://www.w3.org/TR/css-transforms-1/#transform-rendering).

CSS `transform-origin`, `transform-box`, and two-dimensional individual `scale`/`rotate` properties share declaration, CSSOM and feature-query parsing. Transform-list animation pads identities, interpolates compatible primitives, and decomposes absolute matrix tails. An authored identity transform still creates the containing block. Three-dimensional transforms and mixed relative matrix-tail interpolation are not implemented; unsupported interpolation remains discrete instead of inventing a zero percentage basis. SVG descendant transforms remain the existing SVG backend's responsibility.

Inset clip-path animation uses the existing length-expression resolver, retaining percentage and negative edges until box dimensions are known. Other shapes and rounded insets are outside this slice. The Windows painter applies the retained world matrix to local drawing and clips, with balanced ownership through nested opacity/mask groups. Singular transforms do not paint. IPC admission bounds coefficients and nesting and rejects mismatched group boundaries.

An inline SVG root's CSS-owned transform, opacity and supported inset clip are excluded from its raster effects. Root transform/origin and SVG opacity presentation attributes enter the existing author-presentation cascade; the root's resolved transform and opacity are neutralized in the decoder, including SVG-local stylesheet rules. Attributes remain visible to descendant selectors. Legacy SVG transform syntax uses the already-locked svgtypes lexer, preserves single-angle interpolation, and maps three-value rotation pivots to the specified matrix interpolation path; see [SVG transform mapping](https://www.w3.org/TR/css-transforms-1/#svg-transform-functions) and the [outer SVG transform model](https://www.w3.org/TR/SVG2/coords.html#ViewBoxAttribute). These effects are composed exactly once by the retained painter, allowing the metal outline image to remain cached while its inline-style wipe and glow animation change. SVG URL clips/masks and descendant presentation attributes remain in the raster input.

SVG fill and stroke paints also use the document cascade, so rules outside the SVG can match its attributes and HTML ancestors. The existing CSS tokenizer and color parser handle bounded paint values, inheritance, variables, priorities and CSS-wide keywords; resolved paints reach the isolated rasterizer without freezing reusable definition/marker instance inheritance. Existing backend paint servers and fallbacks remain in use, with no new ambient resource fetching. URL normalization preserves complete non-URL functions and later declarations, rather than truncating `rgb(...)` values. See [SVG paint values](https://www.w3.org/TR/SVG2/painting.html#SpecifyingPaint). This is not a full SVG property or paint-animation implementation; reusable definitions still use the backend's local styling/context model, and external-document paint-server fetching is not added.

## SVG pixel snapshots

`SVGSVGElement.viewBox` exposes stable live `SVGAnimatedRect`/`SVGRect` objects, including distinct read-only `animVal`, finite float setters and attribute synchronization. This retains the interoperable legacy API observed in Chrome rather than replacing it with `DOMRect`; see [SVG 1.1 rectangle interfaces](https://www.w3.org/TR/SVG11/types.html#InterfaceSVGAnimatedRect). Other SVG viewBox mixins and SMIL-driven rectangle animation are not included.

Detached Blob images resolve through the realm's private object-URL store and private immutable Blob bytes, then use the existing image decoder. They enforce `img-src`, independently of `connect-src`, without calling an HTTP/file resolver or author-replaced Blob accessors. Superseding source selection cancels the old decode; revocation before selection fails, while a selected decoded image retains its pixels after revocation. See the [File API Blob URL model](https://www.w3.org/TR/FileAPI/#url). This does not add public Fetch Blob support or replace the separate connected-image loader.

SVG image documents admit embedded data-URL fonts through the existing CSS Fonts descriptor parser, validated WOFF/WOFF2/SFNT decoder and usvg/resvg outline renderer. They do not fetch ambient font URLs or resolve local font candidates. Admission is bounded to 64 faces, the existing per-font size limit, and 32 MiB aggregate encoded/decoded font bytes. No new dependency or copied library source is introduced. The outline fixture reuses the repository's existing CC0 Ahem font.

For live main-document inline SVG, the used CSS box establishes the vector viewport before `viewBox`, percentages and `preserveAspectRatio` are resolved; device density controls only the pixel extent. Natural dimensions remain separate for layout, CSSOM and geometry snapshots, rather than making the last HiDPI bitmap the element's intrinsic size. See [SVG viewport establishment](https://www.w3.org/TR/SVG2/coords.html#SVGViewport). A small documented patch to the already-vendored, pinned MIT/Apache-2.0 usvg backend accepts that root viewport as a conversion argument, preserving original attributes for selectors and nested image viewports. Standalone SVG/Blob Image decoding keeps its natural-size contract, and embedded-document inline SVG retains the existing route; this is not a claim of complete SVG 2 viewport support.

The optional live viewport cache retains at most 16 MiB of serialized sources across the existing 256-SVG limit. Source, used viewport and device density independently invalidate published pixels, while compositor-only root effects retain them. Hidden SVGs are refreshed on reveal; removals, malformed replacements and failed raster admission do not publish stale artwork. Optional source-cache exhaustion falls back to the existing bounded natural decoder. Device extents are checked before allocation against existing dimension/pixel/byte limits. Geometry snapshots copy only natural-size metadata, not serialized sources, font snapshots or native trees.

The release `measure_inline_svg_raster_at_used_viewport` command parses and filters an original gradient/path/glow SVG with natural size 700×330, used CSS viewport 140×66 and density 1.25. Four alternating rounds retain 48 samples per route: natural-size rasterization 26.68–28.90 ms (median 28.07), used-viewport rasterization 1.862–2.102 ms (median 1.934). Each result is checked against its independently established size/pixel reference; the corrected 175×83 device raster is intentionally not byte-identical to the old 700×330 natural raster. This is correct viewport-driven work reduction, not a lower quality setting or an application loading/FPS measurement. Samples retain scheduling outliers and run without this agent's other builds or heavy suites.

## Measured image command

The native scaled-image cache retains its 64 MiB bitmap cap but allows a bounded larger working set and admission history. A cyclic set of 64 sprites previously exceeded the 32-key pending history, so none reached its second-use admission. Keys over 4 KiB decline optional cache admission so large data URLs cannot inflate metadata independently of the bitmap cap. Tests compare every native destination pixel with the old policy, verify actual cache reuse and enforce entry/history/key/byte limits. A positive diagonal world transform resolves the destination through GDI's own device conversion before optional cache admission; a saved identity scope preserves its device sampling phase, clipping and layer viewport. This avoids resampling once locally and again through the world transform. Rotation, shear, reflection, non-text mapping modes and RTL retain direct native painting. Translation-only draws retain the existing cache path.

Four alternating reference/candidate rounds of the ignored `benchmark_cyclic_translucent_native_scaling` test retained twelve samples per policy per round (48 per policy), with no overlapping build or heavy suite. Each sample includes 64 warmed native translucent draws and `GdiFlush`; allocation/admission warmup is outside the clock. The old 32-entry/history policy measured 5.79–6.18 ms and the new policy 4.51–4.87 ms. The Rust test control path was a debug build; these are completed native-command elapsed timings on a shared machine, not isolated CPU costs, browser loading times or gameplay FPS.

The release `measure_large_translucent_device_phase_draws` comparison completes six warmed 1200×800 translucent-source draws into a 1605×912 device bitmap under a fractional 1.15 world scale. Each sample includes drawing and `GdiFlush`, with cache admission, backdrop reset and full pixel comparison outside the clock. Four alternating rounds retain 48 samples per policy: direct scaling 28.40–52.38 ms (median 34.20), device-phase caching 17.07–27.77 ms (median 18.49). Busy-machine outliers remain in those ranges, and every sample has byte-identical final pixels. Separate golden tests cover fractional translations near half-pixel boundaries, nonuniform scale, clipping, device/DIB targets, declined transforms and complete DC-state restoration.

Diagonal transformed mask sampling hoists row-independent x coordinates and column-independent y coordinates, retaining the old expression order and center sampling. Rotation and shear use the general inverse path. The release `benchmark_diagonal_mask_sampling` comparison retains 48 samples per policy over four alternating rounds, including every output byte: the general inverse sampler measured 8.98–9.33 ms (median 9.05), versus 1.59–1.85 ms (median 1.67) for the hoisted path. This is a complete mask command, not an application-frame claim.

Sibling SVG serialization shares an immutable first-ID index only within one synchronous resource refresh. A later checkpoint builds a fresh index; separate shadow trees do not share names, the first duplicate ID still wins, and optional metadata exhaustion declines reuse rather than rendering. The release `benchmark_repeated_svg_reference_resolution` command serializes 32 SVGs against an 8,000-ID document and compares every decoder-input string. Four alternating rounds retain 48 samples per policy: independent per-SVG index construction measured 29.41–58.91 ms (median 33.29), versus 0.865–1.475 ms (median 1.278) for batch reuse. These measurements include the serialization command and retain scheduling outliers; no timing comparison overlaps this agent's builds or heavy suites.

CSS keyframe blocks likewise share only their target's synchronous underlying-style input. Each block still begins with its own style clone and resolves declarations through the normal variable, inheritance, shorthand and relative-unit pipeline. The target's own effects are excluded, its parent's sampled inheritance remains visible, and later discovery snapshots observe author/effect changes. This is not a persistent cache across DOM versions or an exception to animation discovery.

The release `measure_keyframe_blocks_with_shared_target_inputs` command resolves twelve blocks for each of 32 targets against 160 style/custom-property rules. Four alternating rounds retain 48 samples per policy and compare every resolved vector: repeated per-block inputs measured 70.35–101.77 ms (median 78.54), versus 11.38–25.15 ms (median 12.30) with target-local inputs. Later effect writes evict the target's composed descendants and pseudos rather than unrelated CSSOM entries, but only when the exact single effect write proves the mutation version. Unknown changes still discard the whole cache. The release `measure_effect_samples_without_discarding_unrelated_styles` command compares every computed value over 48 samples per policy: global eviction 29.23–32.54 ms (median 29.52), target-local eviction 5.16–5.65 ms (median 5.43).

Animation effects also invalidate their element-owned style subtree, not their parent and all its siblings. Author inline-style writes use that narrower root only when the compiled selector graph proves that no `[style]` selector or unknown shadow/scoped stylesheet can observe the write elsewhere. DOM, stylesheet and uncertain selector work retain the conservative route. The release `measure_effect_target_refresh_in_a_large_sibling_set` command verifies the complete resulting style map over four rotating rounds (48 samples per policy): parent-root refresh 19.60–36.60 ms (median 20.93), target-root refresh 0.229–0.539 ms (median 0.349).

Independent viewport-fixed layers retain paint anchors and bounded ownership metadata so a style-only overlay can reflow through the normal layout engine without measuring unrelated normal-flow text. Admission excludes static-position-dependent insets, transformed/contained/clipped/effected ancestors, control and embedded-document work, sticky layers, changed natural image dimensions, uncertain selectors and mixed invalidations. All dirty owners are prepared and checked before any retained ranges are replaced; an unsuccessful proof changes nothing and takes full layout. Fresh overlay text has disjoint fragment-line identities, and current DOM membership, geometry, hit testing, scroll/clip ownership and resize boxes are compared against complete layout in regressions. The release `measure_fixed_overlay_reflow_without_remeasuring_background` command changes one overlay progress transform above 800 paragraphs over four rotating rounds (48 samples per policy): full layout 12.00–16.43 ms (median 13.85), retained fixed-layer reflow 0.200–0.272 ms (median 0.228), with identical paint items and geometry after each sample.

Decoded DOM, CSS, SVG and Canvas pixels share the selected renderer profile's document allowance. Standard remains 64 MiB; the already opt-in graphics profile now allows 128 MiB so overlapping HiDPI title snapshots and particle/main canvases can coexist. Replacement accounting charges current pixels once, checks overflow, and preserves previous pixels after failed admission. Child-frame aggregation uses the same selected allowance. The independent per-batch Canvas/IPC transport caps remain 64 MiB, and the process's 1/2 GiB limits and default setting do not change.

## Reproducible fixtures

- `loading-primitives.html` checks visual widths at 4/25/50/75/100%, real partial transition samples and unchanged logical box sizes.
- `svg-particle-snapshot.html` checks SVG viewBox, serialization, embedded font outline coverage, Blob Image decoding, Canvas drawing and readable pixels, including expanded viewBox snapshots on 1/1.25/2 pixel grids. Breeze and Chrome produced 12,480 and 12,610 covered pixels respectively at the original size; edge antialiasing is not claimed identical.
- `svg-root-effects.html` checks the root presentation cascade, CSS overrides, attribute grammar, transform origins, and resulting visual geometry against Chrome.
- `svg-css-viewport.html` checks CSS-owned root sizing, meet/none alignment, percentage and absolute coordinates without a viewBox, and descendant selectors that depend on the original root attributes.
- `particle-commands.html` checks a 160,000-point normalized-color WebGL2 field, noise/Bezier displacement, texel-fetch gather, blending, completed GPU commands and real start/end pixels. The existing GPU path was already fast; this slice does not claim an improved shader command time.
- `particle-presentation.html` combines an animated inset wipe with the particle field and retains every callback interval, including stalls.
- `alpha-scale-working-set.html` checks a changing Canvas beside 64 repeated scaled SVG images, with real Canvas pixel assertions.

The unchanged Last Stand is a separate functionality check, not the optimization clock. A fresh optimized iteration build's 1284×730.4 CSS / 1.25-scale filmstrip shows partial progress fills, title dissolution, particles arriving at the top-left title and the completed lobby title, without the slow-frame-fallback transition in the resulting DOM. However, the final release filmstrip and a separate no-filmstrip diagnostic run show dissolution followed by the game's ten-frame / 50 ms watchdog cutting the exit short; reliable full gathering remains unfinished. Neither run has a JavaScript failure or decoded-image budget denial. Reduced motion, Low quality and remembered disablement can also legitimately select a plain fade; the browser changes no application gate or preference. Remaining frame presentation cost and Chrome gameplay FPS parity are not claimed fixed. Captures and individual timing samples remain on G: outside commits. Native hidden captures do not measure DWM presentation or high-refresh gameplay parity.

The transition diagnostic identifies a remaining reflected translucent smoke-image draw as a dominant native cost: roughly 60 ms in the captured image item, independently of the already-fast particle shader. This is diagnostic elapsed time, not an isolated-command benchmark claim. Reflected cache experiments were rejected because fractional-scale byte-parity tests exposed different source-texel selection; only the proven positive-diagonal optimization ships. A follow-up should reproduce that reflected draw in a small workload and validate placement, filtering, alpha, clips and ownership before selecting an accelerated backend or sampler.
