# Gameplay frame command costs

Gameplay optimization uses reproducible individual commands with actual pixel/result checks. Unchanged application captures remain separate correctness and bottleneck checks; they are not the optimization baseline. No game assets, reduced-resolution paths, skipped rendering, synthetic delays or site-specific shortcuts are part of these changes.

## Bitmap publication

Straight RGBA8 becomes premultiplied BGRA8 in place, preserving the original exact `(channel * alpha + 127) / 255` equation. On x86-64, the SSE2 baseline handles four pixels at a time; other architectures and short tails retain scalar conversion. Exhaustive channel/alpha pairs, arbitrary byte alignment, trailing bytes and transparent hidden RGB are checked against the scalar contract. There is no runtime requirement for AVX or an optional CPU feature.

The host's WebGL snapshot is a fresh owned byte allocation. Its private clamped view now shares that allocation instead of copying the whole bitmap again. Captured backing-store getters and constructors prevent author replacements from obtaining private storage; the native presentation boundary still takes its independent owned copy. A later draw or source transfer cannot mutate an earlier published bitmap.

Drawing-buffer width/height queries and Canvas resize resets apply extent/reset semantics without exporting GPU pixels. Actual bitmap consumers and paint checkpoints still snapshot the ordered drawing buffer. Regression tests check zero snapshot calls for metadata queries, resize clearing, context loss, Window/Worker exports and independent snapshots after subsequent draws.

## Rendering deadlines

The Windows UI loop owns one anonymous, noninherited, automatic-reset high-resolution waitable timer, using [CreateWaitableTimerExW](https://learn.microsoft.com/windows/win32/api/synchapi/nf-synchapi-createwaitabletimerexw) and [SetWaitableTimerEx](https://learn.microsoft.com/windows/win32/api/synchapi/nf-synchapi-setwaitabletimerex). It waits for either the next document-owned rendering deadline or window input through [MsgWaitForMultipleObjectsEx](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-msgwaitformultipleobjectsex). It never changes global timer resolution, polls an empty queue, creates a timer worker, wakes the computer from sleep or holds a browser-state borrow while dispatching sent messages. Existing WM_TIMER wakeups remain the fallback on unsupported systems and in native modal loops.

The existing logical animation-frame interval remains 16 ms, not an advertised refresh-rate match. Correcting coarse Win32 wake delivery avoids an incidental roughly 31 ms cadence on otherwise light frames. It does not make heavy application frames finish in 16 ms, nor establish screen-presented FPS or parity with Chrome on a high-refresh monitor.

## Numeric command operands

Small converted GPU records own their integer/vector/matrix operands inline using the existing locked `smallvec = 1.15.2` dependency (MIT/Apache-2.0); larger admitted operands spill into owned bounded allocations. Immutable operation-table names are borrowed, and one synchronous ordinary-dispatch record is reused within a batch. Every operation still executes in order with the same native shape, program-generation, context and error validation. No command is deduplicated, delayed past an observation or allowed to retain borrowed author storage.

Fixed Float32 uniform ranges retain the existing public-call snapshot contract. Full fixed ranges avoid an extra view allocation; the private numeric packet retains its element-copy path. A controlled captured typed-array `set` experiment was slower for the small matrix command and was not retained. Regression tests cross packet-capacity boundaries, replace author intrinsics and detach/mutate source storage before observing uniforms in both Window and Worker realms.

Typed uniform admission uses the captured [ArrayBuffer detachment getter](https://tc39.es/ecma262/#sec-get-arraybuffer.prototype.detached), avoiding a temporary empty byte view on every ordinary check. Fixed shared buffers cannot detach and still take their independent early snapshot; growable/resizable buffers remain rejected. The previous constructor-based check remains the fallback if the intrinsic is unavailable. Tests count temporary allocations in both paths and retain detached, empty, shared, overridden-getter and actual native uniform/error checks.

## Native bitmap refresh

Opaque native image draws are classified from the admitted BGRA bytes, never from URLs or author hints. Classification is cached with the bitmap and recomputed after synchronized updates. Fully opaque, untinted images use `StretchBlt` with `COLORONCOLOR`, matching [AlphaBlend's forced sampling mode](https://learn.microsoft.com/windows/win32/api/wingdi/nf-wingdi-alphablend); translucent and tinted images keep their existing source-over path. Native copy failures also fall back to blending, and source selection/stretch-mode state is restored. The [isolated opaque draw workload](../benchmarks/pixels/opaque-blit.rs) checks every resulting BGRA byte for unscaled, enlarged, reduced, translated and clipped rectangles before recording three rotated orders of 25 completed draws. On this shared machine, 1536×658 to 1920×824 draws measured 2.48–3.01 ms with blending versus 0.70–0.82 ms with copying; all individual samples are retained on G:. These are command timings, not gameplay FPS.

The guarded hidden benchmark's opt-in `-NativePaintTrace` replays the actual native display-list painter into an owned compatible bitmap before acknowledging each visual presentation. Its bounded 256-sample tails record allocation/paint/flush elapsed time, item categories, the slowest image dimensions, and document-installation stages (accessibility, display list, image/glyph admission, metadata, paint, metrics); it creates no visible UI and exports neither image pixels nor resource URLs in those timing samples. Ordinary browsing does not enable the clocks. This models native backbuffer work and acknowledgment pressure, not DWM/window presentation. The user's 5.6 FPS Breeze versus 144 FPS Chrome reports remain the visible-game baseline; hidden callback or presentation intervals must not be substituted for a verified gameplay FPS improvement.

The browser's UI-thread image cache reuses a same-size DIB allocation when immutable presentation bytes change. It first completes the owning thread's GDI batch with [GdiFlush](https://learn.microsoft.com/windows/win32/api/wingdi/nf-wingdi-gdiflush), as required before CPU access to [CreateDIBSection storage](https://learn.microsoft.com/windows/win32/api/wingdi/nf-wingdi-createdibsection), then copies the complete owned pixel buffer. Resize, malformed input or synchronization failure retire the old allocation; derived tint bitmaps are invalidated, and document/resource retirement still releases every handle. Drawing restores selected source bitmaps before cache updates. Tests verify earlier drawings retain earlier pixels, the next draw sees the updated pixels, and peer/tinted/resized resources have independent lifetimes.

## Reproduction

### Translucent native-image painting

Sparse unscaled translucent images retain at most 16 disjoint coarse rectangles covering every nonzero BGRA byte. Fully zero interiors do not affect source-over blending, so they can be omitted without treating malformed nonzero RGB/zero-alpha bytes as transparent. Cached native-resampled images derive the same conservative cover from their final destination-sized pixels, so skipped regions cannot change the sampling phase. Dense, fragmented, small, uncached scaled and tinted images keep the original full draw. Native tests compare all output channels under translated viewports and complex rounded clipping, including one-pixel extent differences and dense-cover fallbacks. Source updates discard the derived coverage. The isolated unscaled sparse-border command retained three rotated orders of 25 samples: full blending ranged from 0.869 to 1.218 ms versus 0.263 to 0.412 ms for the disjoint strips; these are command timings, not game FPS.

Repeated scaled translucent images cache a native `AlphaBlend` resampling into an owned zero-initialized DIB, then blend the cached pixels at their exact destination extent. `StretchBlt` is deliberately not used for this cache: an isolated experiment changed 397,746 output bytes despite selecting `COLORONCOLOR`. The implemented path uses [AlphaBlend's documented resampling](https://learn.microsoft.com/windows/win32/api/wingdi/nf-wingdi-alphablend) and passed every-channel comparisons for upscaling, downscaling, one-pixel extent differences, clipping and translated viewports. Admission requires a second identical paint; updates, removals and document replacement invalidate derived pixels. The LRU is limited to 32 entries and 64 MiB, with small or oversized draws retaining the original path. An isolated 1,200×800-to-2,880×1,235 draw retained three rotated orders of 25 samples: direct resampling ranged from 12.255 to 16.552 ms versus 6.703 to 9.309 ms for reuse, excluding the one-time cache construction. This is a repeated-command improvement, not a claim that gameplay now matches Chrome.

### Mask coverage multiplication

The native mask painter hoists invariant horizontal source coordinates and computes vertical coordinates once per row, retaining the original center-sampling expression rather than accumulating floating-point steps. Its x86-64 SSE2 baseline multiplies four RGB pixels by coverage with exact `(channel * alpha + 127) / 255` rounding, replacing destination alpha with mask alpha as before; scalar tails and other architectures retain the same equation. Mask RGB and previous destination alpha remain ignored. Exhaustive channel/alpha pairs, arbitrary byte alignment, trailing bytes, translated clips, scaled sampling and native nested mask/opacity backdrops are regression-tested. The [isolated mask command](../benchmarks/pixels/mask-composite.rs) includes allocation/result checks outside the clock, five warmups and three rotated orders of 20 samples. Unscaled samples ranged from 6.482–9.822 ms before versus 0.514–0.577 ms after; scaled samples were 6.511–6.810 ms versus 1.001–1.094 ms. All individual samples and busy-machine outliers are retained on G:; these are completed CPU command times, not screen FPS.

### Proven local content invalidation

HTML `textContent` replacement still creates fresh text-node identity and consumes the existing tree/node budgets, as required by [DOM string replace-all](https://dom.spec.whatwg.org/#concept-node-string-replace-all). If inspection proves that only text/comment children were replaced, the cascade can retain bounded dirty subtrees instead of widening solely because some unrelated rule contains [`:has()`](https://drafts.csswg.org/selectors/#relational). This proof can coalesce with declaration writes and a closed set of graphics-coordinate/path attributes. Unknown attributes, element membership, control state and unclassified mutations clear it. Compiled dependencies retain document-wide refresh for relevant relative attribute selectors, text-sensitive `:empty`/direction/validity rules, slots and automatic directionality; shadow/scoped rules do not use the new ordinary-selector proof, and style-element content still rebuilds rules with its original dirty-root scope. Tests compare retained styles with a fresh full cascade, including empty siblings, inherited direction, removed elements, SVG attributes, scoped/slotted rules and stylesheet changes. The [local content command](../benchmarks/ui/fixtures/local-content-cascade.html) separates lazy computed-style queries from completed renderer cascade/layout observations (`?geometry=1`) in a 600-node unrelated subtree and verifies both local results and genuine nonlocal membership changes; it is not a game-specific selector exemption.

Each immutable layout pass also retains its normalized ordinary child lists, rather than reconstructing composed children, pseudo-elements and flattened `display: contents` descendants on every traversal. This is a pass-owned cache, not a cross-frame DOM cache: a new pass observes new topology and styles. Empty leaves remain allocation-free, while table-column pruning retains an explicit empty list. Regression tests preserve shadow-slot order, pseudo-element placement, top-layer exclusion, anonymous-table behavior and author DOM identity.

- [Gameplay commands](../benchmarks/ui/fixtures/gameplay-commands.html) exercises changing 256-component float uniforms, 16-component matrices, 64 KiB texture subuploads and drawing-buffer size queries. Each measured block includes `gl.finish()`; final real shader/texture pixels and uniform values are checked. Five individual per-command block samples remain in the result Canvas's `data-*` attributes, captured alongside the compact title average.
- [Image-source uploads](../benchmarks/ui/fixtures/gameplay-image-upload.html) measures completed RGBA8 ImageData uploads, retaining five individual samples for both unchanged and flipped rows after two warmups. Mutating the source after upload must not alter the real texture pixels. The bulk path preserves crop offsets and volume layer gaps; premultiplication, packed/integer and high-precision conversions retain their existing paths.
- [Dirty bitmap queries](../benchmarks/ui/fixtures/gameplay-bitmap-query.html) isolates the width/height command on a dirty 1,024-square drawing buffer. Clear and GPU completion are outside the query clock; the final pixel and GL error check prove that the query did not consume or corrupt rendering.
- [Frame cadence](../benchmarks/ui/fixtures/gameplay-frame-cadence.html) checks real WebGL clears across 65 animation callbacks. It reports the mean, median and complete range of 64 intervals, including startup stalls; this is callback cadence, not a GPU execution or screen-presentation counter.
- [Pixel conversion](../benchmarks/pixels/premultiply.rs) is a dependency-free standalone Rust command workload. Compile with `rustc --edition=2024 -C opt-level=3 -C target-cpu=x86-64`, with the executable and temporary files on G:. Allocation, source copying and exhaustive result checking remain outside the conversion clock. It retains 20 individual samples after five warmups for each opaque, partial-alpha and mixed-alpha million-pixel input.
- [DIB refresh](../benchmarks/pixels/dib-refresh.rs) is a dependency-free standalone Windows workload compiled with `rustc --edition=2024 -C opt-level=3`. It creates no window. Reallocation and synchronized reuse admit the same changed 1,024-square BGRA image; every resulting byte is checked outside the clock. Three rotated reference/candidate orders retain 20 samples each after five warmups, including synchronization rather than comparing queued drawing with completed work. This isolates bitmap admission, not painting or screen FPS.

Run one hidden browser worker, rotate sequential candidate/reference order, preserve every sample and busy-machine outlier, and keep this agent's builds/full suites out of timing windows. Diagnostic iteration binaries use the `performance` profile; published browser measurements require a rebuilt final `release` executable. Other agents still affect scheduling, so elapsed values are not isolated CPU costs. Original reports and screenshots remain on G: and outside commits.

For statistical source-coordinate investigation only, `BREEZE_DIAGNOSTIC_CPU_SAMPLING=frames` delays sampling until 20 seconds after diagnostics are enabled, selects the private timer-callback hook rather than label/presentation calls, exports at most four completed author tasks lasting at least 8 ms, then stops creating profilers. An optional `BREEZE_DIAGNOSTIC_CPU_SAMPLING_DELAY_MS` accepts an integer from 0 through 60,000 ms to defer the capture further; invalid values use the default 20 seconds. It uses the existing bounded numeric-only V8 report and ordinary execution watchdog; no author names, source or arguments are inspected. Sampling has overhead and must be disabled for timing comparisons. The original `=1` startup/failure mode is unchanged. Neither mode is enabled by ordinary browsing.
